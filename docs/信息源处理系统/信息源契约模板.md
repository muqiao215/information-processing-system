# 信息源契约模板

## 使用场景

新增信息源、把现有脚本改成 cron、或把某个仓库 / feed / API 纳入 digest 前，先按这个模板登记。

## Source Contract

| 字段 | 填写要求 |
| --- | --- |
| `source_id` | 稳定短 ID，用于 cron、输出文件和文档引用 |
| `status` | `candidate` / `active` / `paused` / `retired` |
| `layer` | `source collector` / `selector` / `synthesizer` / `artifact generator` / `ops telemetry` |
| `source_of_truth` | 真正可信的上游，如 GitHub repo、RSS feed、arXiv API、原网页 |
| `access_path` | 本机访问路径，如 `gh`、`feedparser`、Jina Reader、脚本、CDP、仓库 pull |
| `preferred_tool` | 首选工具 |
| `fallback_tool` | 首选工具失败后的 fallback |
| `freshness_policy` | 每次 live 拉取、允许本地缓存、还是允许上游快照 |
| `selection_policy` | 如何过滤、打分、去重、排序 |
| `output_contract` | 必须生成哪些文件或报告 |
| `failure_behavior` | 失败时停止、降级、跳过、使用缓存，还是部分成功 |
| `downstream_consumers` | 哪些 digest、NotebookLM、Telegram 或其他任务会消费它 |
| `owner` | 维护归属 |
| `last_verified` | 最近验证日期 |
| `default_fetch_cascade` | 对公开网页 / X 是否启用默认多层抓取级联 |

## YAML Skeleton

```yaml
source_id:
status:
layer:
source_of_truth:
access_path:
preferred_tool:
fallback_tool:
freshness_policy:
selection_policy:
output_contract:
failure_behavior:
downstream_consumers:
default_fetch_cascade:
owner: Muqiao
last_verified:
```

## 最低验收标准

- `source_of_truth` 和 `access_path` 分开。
- 至少有一个稳定人读输出或 JSON manifest。
- 失败行为明确，不允许 silent fake success。
- 如果要进入主 digest，必须能追溯原始链接或原始记录。
- 如果要进入 NotebookLM，下游 manifest 必须包含可导入 URL 或 fallback markdown source。
- 如果是公开网页或 X/Twitter，默认应声明是否启用 `r.jina.ai -> defuddle.md -> bot UA -> AMP -> archive.today -> agent-fetch` 级联。

## 分类判断

| 问题 | 结论 |
| --- | --- |
| 它直接接触原始上游吗？ | 是 `source collector` |
| 它只负责挑选、过滤、排序吗？ | 是 `selector` |
| 它把已选内容改成中文简报吗？ | 是 `synthesizer` |
| 它只生成 NotebookLM 报告、视频、幻灯片吗？ | 是 `artifact generator` |
| 它只检查额度、服务健康、账号池吗？ | 是 `ops telemetry`，不要放进内容源 |
