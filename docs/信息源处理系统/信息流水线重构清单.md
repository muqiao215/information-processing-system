# 信息流水线重构清单

## 目标

把当前“多个 cron 各自产出 latest 文件”的形态，重构成 APD 风格的两层流水线：

1. 信息获取层：负责 source collection / selection / bundle。
2. 知识消化层：负责 NotebookLM ingest / report / artifacts / publishing。

## 推荐新增运行目录

```text
/root/.ductor/workspace/output_to_user/information_pipeline/
  acquisition/YYYY-MM-DD/
  bundles/YYYY-MM-DD/
  digestion/YYYY-MM-DD/
  artifacts/YYYY-MM-DD/
  ledgers/YYYY-MM-DD.json
```

`output_to_user/*latest*` 保留为兼容入口，但不再作为长期资产主路径。

## 推荐新增 cron

### `daily-knowledge-pack-builder`

职责：

- 读取各 source cron 的 `*_latest.json`。
- 去重、标准化、补 fallback markdown。
- 生成 canonical `knowledge_pack`。

输入候选：

- `/root/.ductor/workspace/output_to_user/ai_builders_digest_sources_latest.json`
- `/root/.ductor/workspace/output_to_user/builderpulse_opportunity_radar_sources_latest.json`
- `/root/.ductor/workspace/output_to_user/arxiv_llm_memory_discovery_latest.json`

输出：

- `/root/.ductor/workspace/output_to_user/knowledge_pack_latest.json`
- `/root/.ductor/workspace/output_to_user/knowledge_pack_latest.md`
- `/root/.ductor/workspace/output_to_user/information_pipeline/bundles/YYYY-MM-DD/knowledge_pack.json`
- `/root/.ductor/workspace/output_to_user/information_pipeline/bundles/YYYY-MM-DD/knowledge_pack.md`

### 改造 `daily-notebooklm-content-gen`

职责变化：

- 从读取 `ai_builders_digest_sources_latest.json` 改成优先读取 `knowledge_pack_latest.json`。
- 只做 NotebookLM ingest + report。
- 不再负责 source selection 或 manifest 兼容。

### 改造 `daily-notebooklm-artifact-trigger`

职责变化：

- 继续触发 slide / video。
- 写入统一 artifact ledger。
- 不等待 artifact ready。

### 可选新增 `daily-information-publishing`

职责：

- 读取 artifact ledger。
- 后续发布到 portal / HuggingFace / 其他展示面。
- 暂不默认接抖音。

## 推荐新增脚本

```text
tools/knowledge_pipeline/
  schemas/knowledge_pack.schema.json
  normalization/build_knowledge_pack.py
```

脚本职责：

- 读取 source manifests。
- 标准化 item schema。
- 对 URL / PDF / markdown source 分流。
- 对 X / 普通网页保留 cascade fetch 入口。
- 写入 `knowledge_pack` 与 fallback markdown。

## 推荐 schema

### Knowledge Pack Item

```json
{
  "item_id": "source_id:stable_hash",
  "source_id": "follow-builders",
  "source_type": "tweet",
  "source_of_truth": "original URL or feed",
  "access_path": "fetch script / reader / repo archive",
  "title": "...",
  "url": "...",
  "summary": "...",
  "raw_text": "...",
  "selected_reason": "...",
  "tags": [],
  "freshness": {
    "published_at": "...",
    "generated_at": "..."
  },
  "content_type": "url | markdown | pdf | x_post | repo_archive",
  "import_targets": [],
  "import_policy": {
    "preferred": "url",
    "fallback": "markdown"
  },
  "fallback_content": "...",
  "metadata": {}
}
```

### Knowledge Pack

```json
{
  "date": "YYYY-MM-DD",
  "pack_id": "knowledge-pack-YYYY-MM-DD",
  "item_count": 0,
  "items": [],
  "fallback_markdown_path": "...",
  "generated_at": "...",
  "input_manifests": {},
  "notes": []
}
```

### Artifact Ledger

```json
{
  "date": "YYYY-MM-DD",
  "pack_id": "...",
  "notebook_id": "...",
  "report_path": "...",
  "report_artifact_id": "...",
  "slide_deck_artifact_id": "...",
  "video_artifact_id": "...",
  "status": "REPORT_OK | ARTIFACT_TRIGGERED | ASYNC_PENDING | ERROR",
  "updated_at": "...",
  "last_error": null
}
```

## 迁移顺序

1. 先新增 `knowledge_pack` schema 与 builder，不改现有 digest cron。
2. 手动跑 builder，确认能消费现有三个 source output。
3. 创建 `daily-knowledge-pack-builder` cron。
4. 改 `daily-notebooklm-content-gen` 优先读取 `knowledge_pack_latest.json`。
5. 改 `daily-notebooklm-artifact-trigger` 写 artifact ledger。
6. Obsidian 注册表从“Active Sources / Downstream Consumers”扩成“Acquisition / Digestion / Publishing”。
7. 再考虑 APD portal / HuggingFace publishing 是否接入。

## 风险

- 如果直接改 NotebookLM cron 而没有中间 bundle，会把 source 兼容逻辑继续塞进 artifact 层。
- 如果直接复制 APD browser bot，会和本机 server-browser / CDP 主线冲突。
- 如果过早接 publishing，会让“内容获取”和“对外发布”耦合。
- 如果继续只用 `latest` 文件做长期记录，后续无法回溯每天进入 NotebookLM 的真实 source set。
