# 信息获取层与知识消化层分离

## 核心决定

本地信息体系以后分成两条主线：

1. 信息获取层：负责发现、抓取、清洗、筛选信息源。
2. 知识消化层：负责把已选内容送入 NotebookLM / 归档 / 生成报告、视频、幻灯片、发布页。

这两个层级不要再混在同一个 cron 或同一张表里解释。

## 为什么借鉴 APD

`auto-paper-digest` 的价值不只是论文抓取。

它真正值得借鉴的是流水线骨架：

- 每个对象入库。
- 每个阶段有状态。
- 源文件、PDF、digest、video、slides 各自归档。
- NotebookLM 只是中间处理器，不是整个系统的唯一中心。
- 发布到 HuggingFace / 抖音 / portal 属于下游发布层。

这和当前本机的信息处理方向一致：

- 先有 `follow-builders` / `BuilderPulse` / arXiv 这类采集源。
- 再统一成可导入 NotebookLM 的 source bundle。
- 再生成 report / slides / video。
- 最后沉淀为可长期检索和复用的知识资产。

## 新分层

| 层级 | 责任 | 当前例子 | 后续方向 |
| --- | --- | --- | --- |
| acquisition / 信息获取 | 接触上游，抓取原始条目、正文、PDF、RSS、X 单条、GitHub archive | `follow-builders`, `BuilderPulse`, `arxiv-llm-memory-discovery` | 加统一抓取 cascade 与 source object |
| selection / 选题过滤 | 去重、打分、筛掉噪声、选出值得消化的 item | `arxiv-llm-memory-discovery`, `BuilderPulse` 机会提取 | 统一 selected item schema |
| bundle / 入库包 | 把多个源统一成 NotebookLM 可消费的 canonical pack 与 fallback markdown | 目前分散在 `*_sources_latest.json` | 新增 `knowledge_pack` |
| digestion / 知识消化 | 创建 NotebookLM notebook、导入 source、生成 report | `daily-notebooklm-content-gen` | 改为消费统一 bundle |
| artifact / 产物生成 | 触发 slide deck / video / audio 等异步产物 | `daily-notebooklm-artifact-trigger` | 加 artifact ledger |
| publishing / 发布展示 | HuggingFace / 抖音 / portal / 历史页面 | APD 参考实现 | 暂不接主链，作为后续扩展 |

## 关键边界

### 信息获取层不做的事

- 不创建 NotebookLM notebook。
- 不触发视频、幻灯片或 podcast。
- 不承担最终知识归档。
- 不把“读到的摘要”冒充“已消化的知识”。

### 知识消化层不做的事

- 不直接扫描 X、RSS、GitHub Trending、arXiv。
- 不临时决定 source priority。
- 不从标题硬编正文。
- 不绕过上游 source manifest。

## APD 中要吸收的实现习惯

### 1. 状态机

当前建议先不用强上 SQLite，可先用 JSON ledger，字段保持接近 APD：

```json
{
  "item_id": "...",
  "source_id": "...",
  "status": "COLLECTED | SELECTED | BUNDLED | IMPORTED | REPORT_OK | ARTIFACT_TRIGGERED | PUBLISHED | ERROR",
  "source_url": "...",
  "local_text_path": "...",
  "notebook_id": "...",
  "report_path": "...",
  "artifact_ids": {},
  "last_error": null,
  "updated_at": "..."
}
```

### 2. 分目录归档

建议后续把 `output_to_user/*latest*` 降为兼容入口，长期资产归到日期目录：

```text
output_to_user/information_pipeline/
  acquisition/YYYY-MM-DD/
  bundles/YYYY-MM-DD/
  digestion/YYYY-MM-DD/
  artifacts/YYYY-MM-DD/
  ledgers/YYYY-MM-DD.json
```

### 3. NotebookLM 只作为处理器

NotebookLM 负责：

- ingest source
- report
- slide / video / audio
- chat / research when explicitly needed

但 source selection、fallback fetching、artifact ledger 不应散落在 NotebookLM cron 内部。

### 4. 发布层独立

APD 的 HuggingFace / 抖音 / portal 很有参考价值，但不能绑死主链。

后续如果要做对外展示，应作为独立 publishing layer：

- 读取 artifact ledger。
- 读取 report / video / slides。
- 生成 portal 或发布任务。

## 不采纳的 APD 实现细节

- 不复制 APD 的 NotebookLM Playwright browser bot；本机已经统一到 server-browser + CDP `127.0.0.1:9222`。
- 不把 HF papers 当成通用信息源主线。
- 不把 Douyin / HuggingFace 发布作为信息获取层的一部分。
- 不引入需要额外 API key 的预处理默认路径。
- 不让每个 source cron 自己临时决定 NotebookLM 输入格式。
