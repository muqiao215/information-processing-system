# 信息源契约模板

## 使用场景

新增信息源、把现有脚本改成 cron、或把某个仓库 / feed / API 纳入 digest 前，先按这个模板登记。

## Source Contract

| 字段 | 填写要求 |
| --- | --- |
| `source_id` | 稳定短 ID，用于 cron、输出文件和文档引用 |
| `status` | `candidate` / `active` / `paused` / `retired` |
| `layer` | `source collector` / `acquisition orchestrator` / `acquisition adapter` / `selector` / `synthesizer` / `artifact generator` / `ops telemetry` |
| `source_of_truth` | 真正可信的上游，如 GitHub repo、RSS feed、arXiv API、原网页 |
| `access_path` | 本机访问路径，如 `gh`、`feedparser`、Jina Reader、脚本、CDP、仓库 pull |
| `acquisition_recipe` | 公开网页 / X / 单链接等需要编排抓取时采用的 recipe；普通 collector 可写 `none` |
| `adapter_set` | 该 recipe 可调用的 adapter 列表，按默认优先级排列 |
| `optional_adapters` | 只有显式启用时才允许进入的 adapter，如 Firecrawl |
| `freshness_policy` | 每次 live 拉取、允许本地缓存、还是允许上游快照 |
| `selection_policy` | 如何过滤、打分、去重、排序 |
| `promotion_policy` | 什么条件下可以从 acquisition candidate 提升为 `knowledge_pack` item |
| `ledger_contract` | 至少记录哪些 attempt 字段，如 adapter、status、error、selected_result、promotion_note |
| `output_contract` | 必须生成哪些文件或报告 |
| `failure_behavior` | 失败时停止、降级、跳过、使用缓存，还是部分成功 |
| `downstream_consumers` | 哪些 digest、NotebookLM、Telegram 或其他任务会消费它 |
| `owner` | 维护归属 |
| `last_verified` | 最近验证日期 |
| `default_acquisition_path` | 对公开网页 / X 是否启用默认 acquisition recipe，以及 no-extra-key 是否优先 |

```yaml

owner: Muqiao
```

## 最低验收标准

- `source_of_truth` 和 `access_path` 分开。
- 至少有一个稳定人读输出或 JSON manifest。
- 失败行为明确，不允许 silent fake success。
- 如果要进入主 digest，必须能追溯原始链接或原始记录。
- 如果要进入 NotebookLM，下游 manifest 必须包含可导入 URL 或 fallback markdown source。
- 如果是公开网页或 X/Twitter，默认应声明 acquisition recipe、adapter set、ledger 最低字段，以及是否坚持 no-extra-key 优先。
- Firecrawl / web-agent 只能作为 `optional_adapters` 或参考实现，不能在模板里默认写成必经路径。

## 分类判断

| 问题 | 结论 |
| --- | --- |
| 它直接接触原始上游吗？ | 是 `source collector` |
| 它负责按 item type 选择抓取 recipe、串联 adapter、记录 ledger 吗？ | 是 `acquisition orchestrator` |
| 它只是被编排层调用的一种抓取工具或 reader 吗？ | 是 `acquisition adapter` |
| 它只负责挑选、过滤、排序吗？ | 是 `selector` |
| 它把已选内容改成中文简报吗？ | 是 `synthesizer` |
| 它只生成 NotebookLM 报告、视频、幻灯片吗？ | 是 `artifact generator` |
| 它只检查额度、服务健康、账号池吗？ | 是 `ops telemetry`，不要放进内容源 |
